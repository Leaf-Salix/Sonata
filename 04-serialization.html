Tutorial 4 - 序列化与 Fingerprint

提问：Score 怎么序列化成 JSON？

score_to_dict 把 Score 转成一个确定性的字典，score_to_json 转成 JSON 字符串：

from sonata import score_to_json

json_str = score_to_json(score, indent=2)

关键：sort_keys=True 保证相同内容的 Score 总是产生相同的 JSON。如果不排序，同一个 Score 在不同时间序列化可能产生不同的 key 顺序，导致 fingerprint 不同但实际内容相同。

提问：Fingerprint 是什么？解决了什么问题？

Fingerprint 是 Score 的计算身份标识——一个 SHA-256 哈希值。

from sonata import score_fingerprint

fp = score_fingerprint(score)
print(fp)  # "a1b2c3d4..."

用途：把 fingerprint 当作 cache key。两个 Score 的 fingerprint 相同 → 计算内容完全一样 → 可以复用编译结果。

提问：Fingerprint 包含什么、不包含什么？为什么？

{
    "fingerprint_version": 1,
    "identity": {
        "name": "matmul_bias",
        "tasks": [...],
        "dependencies": [...],
        "shape_assumptions": [...]
    }
}
包含不包含理由
name, tasks, dependencies, shape_assumptions runtime_target, metadata 前者决定了"算什么"（计算身份），后者是"怎么跑"（执行身份）

考虑这两个 Score：

# 这两个 Score 做的计算完全一样：
score_a = Score(name="matmul", tasks=(...),
    runtime_target=RuntimeTarget(function_name="build_matmul_graph"))
score_b = Score(name="matmul", tasks=(...),
    runtime_target=RuntimeTarget(function_name="build_matmul_v2_graph"))

# fingerprint 相同！因为 fingerprint 只看"算什么"，不看"怎么跑"
# 这提高了缓存命中率 — 同一计算不同 runtime 配置共享缓存
四系统共识：Inductor、XLA、TVM、CUDA Graphs 都区分"计算身份"和"执行身份"。 Sonata 跟随这个最佳实践。详见 Tutorial 06 的工业界经验部分。

提问：fingerprint_version 有什么用？

FINGERPRINT_VERSION = 1

版本号参与 hash 计算。如果将来 hash 的规则变了（比如加了新字段），把版本号改为 2。 由于版本号本身在 hash payload 里，旧的 fingerprint 值不会再被匹配到——旧缓存自动失效，不需要手动清理。

提问：shape_assumptions 怎么影响 fingerprint？

ShapeAssumption 是 fingerprint 的一部分，所以：

  • x 的形状从 [32, 768] 变成 [64, 768] → fingerprint 不同 → 缓存未命中 → 新 Score 被提取
  • 这正是 guard 机制的核心——形状变化自动触发重新规划

这也是为什么动态维度（-1、0）不能记录为 ShapeAssumption 的原因—— 如果记录了"假"的静态值，fingerprint 会因为一个不确定的维度而产生，导致缓存可能被错误命中。

提问：EligibilityResult 也能序列化吗？

from sonata import eligibility_result_to_dict

result_dict = eligibility_result_to_dict(result)

输出包含 eligible、reasons、reason_details，以及（如果有的话）完整的 score 字典。 Schema version 也嵌入在输出中（当前 = 1），将来 breaking change 时版本号递增，消费者可检测格式变化。

提问：Schema Version 有哪些？

SCORE_SCHEMA_VERSION = 1              # score_to_dict 输出的版本
ELIGIBILITY_RESULT_SCHEMA_VERSION = 1  # eligibility_result_to_dict 输出的版本
FINGERPRINT_VERSION = 1               # fingerprint hash payload 的版本

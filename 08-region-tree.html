Tutorial 8 - Region Tree：层次化区域管理

提问：为什么需要 RegionTree？

v0.4 的 RegionMap 是一个扁平的区域列表：一个 IR 图被切成若干段， 每段标记为 static 或 dynamic。这在大多数情况下够用，但遇到复杂 IR 时有两个问题：

  1. 无法表达层次关系：一个 static 区域可能包含多个子区域（例如嵌套的函数调用）， 但扁平结构看不到这种父子关系。
  2. 无法独立管理缓存：如果图的某一部分变化了（比如某个 guard 失效）， 扁平结构只能整个失效或不失效，无法精确到"只失效受影响的子树"。
类比：RegionMap 像一张清单——列出所有区域，不分层次。 RegionTree 像一棵文件系统目录树——每个文件夹（节点）可以有子文件夹， 你可以单独删除某个子文件夹而不影响其他部分。

提问：RegionTree 的数据结构是什么？

RegionTree 由两类节点组成：

类型角色特点
RegionTreeNode树的一个节点包含一个 Region、可选的 Score、子节点列表、子树指纹
RegionTree整棵树的容器持有 root 节点，提供遍历和查询方法
@dataclass(frozen=True)
class RegionTreeNode:
    region: Region                           # 区域类型（static/dynamic）
    children: tuple[RegionTreeNode, ...]     # 子节点
    score: Optional[Score] = None            # 该区域的 Score（静态区域才有）
    _fingerprint_cache: Optional[str] = None # 子树指纹缓存

每个节点是 frozen=True 的不可变数据类——修改时必须创建新实例。 这保证了指纹的一致性：同一个节点在任何时刻都有相同的指纹。

提问：怎么从 RegionMap 构建 RegionTree？

使用 build_region_tree() 函数：

from sonata import extract_regions, RegionTree
from sonata.regions import build_region_tree

# 1. 先提取扁平区域
region_map = extract_regions(ir_node)

# 2. 构建层次化树
tree = build_region_tree(region_map)

构建算法的核心逻辑：

  1. 为每个 Region 创建一个叶子节点
  2. 将连续的 dynamic 区域归入其前面的 static 区域作为子节点
  3. 第一个 static 区域成为整棵树的 root
注意：当前算法采用"静态 parent + 动态 children"策略。 如果 IR 的第一个区域就是 dynamic 的，它会成为 root（standalone）。

提问：RegionTreeNode 有哪些查询方法？

node = tree.root

# 节点属性
node.is_leaf           # True if 无子节点
node.region_status     # "static" / "dynamic" / "mixed"
node.is_static_subtree # True if 整个子树都是 static
node.fingerprint       # 子树的 SHA-256 指纹

# 树级查询
tree.all_nodes         # BFS 遍历所有节点
tree.static_subtrees() # 所有"最大静态子树"的根节点
tree.dynamic_nodes()   # 所有 dynamic 节点
tree.static_ratio      # 静态节点占比

region_status 三态

状态含义场景
"static"节点和所有子节点都是 static纯静态子树，可以完整规划
"dynamic"节点本身是 dynamic控制流节点，需要 fallback
"mixed"节点是 static，但有 dynamic 子节点部分可用，需要混合策略

提问：子树指纹是怎么计算的？

每个 RegionTreeNode 的指纹是整个子树的哈希值，包含：

  • 节点自身的 region_id、kind、node_count
  • 节点的 Score（如果有）的 task_count、dep_count、guard_count
  • 所有子节点的递归指纹
# 指纹计算伪代码
fingerprint_payload = {
    "fingerprint_version": 1,
    "identity": {
        "type": "region_tree_node",
        "region_id": self.region.region_id,
        "region_kind": self.region.kind,
        "node_count": self.region.node_count,
        # ... score identity if present ...
        "children": [child.fingerprint for child in self.children],
    },
}
fingerprint = sha256(json.dumps(fingerprint_payload))

这意味着：如果子树中任何一个节点变化（比如 Score 更新），整棵子树的指纹都会变化。 而兄弟子树的指纹不受影响——这就是层次化管理的核心价值。

提问：怎么更新节点？

因为节点是 frozen 的，"更新"实际上是创建新实例：

# 更新节点的 Score
new_node = node.update_score(new_score)
# → 新节点有新的 fingerprint（基于 score_fingerprint）

# 更新子节点
new_node = node.update_children(new_children_tuple)
# → 新节点有新的 fingerprint（基于新的子树指纹）
不变性的好处：旧节点和新节点可以同时存在。 缓存系统可以用旧指纹找到旧条目，用新指纹存储新条目，不会互相干扰。

提问：缓存怎么和 RegionTree 配合？

v0.11 添加了三个函数来管理 RegionTree 的缓存：

from sonata.regions import (
    store_region_tree,
    lookup_region_tree,
    invalidate_region_tree,
)

# 存储：遍历树，为每个节点计算指纹并存入缓存
path_map = store_region_tree(tree, plan_handle_payload, cache)
# path_map: {"root" → fingerprint, "root.child[0]" → fingerprint, ...}

# 查询：按路径查找某个区域的缓存
payload = lookup_region_tree("root.child[0]", cache, path_to_fingerprint=path_map)

# 失效：当某个节点的 guard 失效，清除该节点及所有子孙的缓存
removed = invalidate_region_tree(tree, violated_node, cache, path_to_fingerprint=path_map)

失效策略是保守的：只清除受影响的子树，祖先节点的缓存保留。 这避免了"一个 guard 失效导致整棵树重算"的问题。

提问：怎么在代码中使用？

from sonata import extract_regions, check_region_eligibility
from sonata.regions import build_region_tree

# 完整的区域级 eligibility 检查
result = check_region_eligibility(ir_node, entry_name="my_graph")

if result.eligible:
    meta = result.metadata
    print(f"Regions: {meta['region_count']}")
    print(f"Static: {meta['static_region_count']}")
    print(f"Dynamic: {meta['dynamic_region_count']}")
    print(f"Static ratio: {meta.get('static_ratio', 0):.0%}")

    # 访问 RegionTree
    region_tree = meta.get('region_tree')
    if region_tree:
        for node in region_tree.static_subtrees():
            print(f"Static subtree: region_{node.region.region_id} "
                  f"({node.region_status})")

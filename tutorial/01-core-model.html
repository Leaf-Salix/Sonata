Tutorial 1 - Score 数据模型

提问：用一个具体例子，Score 长什么样？

假设我们有这样一个 PyPTO 程序（矩阵乘法 + 偏置加法）：

# PyPTO DSL — 一个简单的矩阵乘法 + 偏置加法
def matmul_bias(x, w, b):
    y = matmul(x, w)        # task 0: matmul, AIC core
    z = add(y, b)           # task 1: add, AIV core
    return z

Sonata 的 check_static_eligibility() 会从中提取出如下 Score：

// score_to_json() 输出 — 这就是"静态执行计划"
{
  "schema_version": 1,

  "tasks": [

      "name": "matmul",
      "args": ["x", "w", "y"],
      "arg_directions": ["input", "input", "output"],
      "arg_storage_keys": ["param:0:x", "param:1:w", "alloc:y"]
    },
    {
      "task_id": 1, "func_id": 1, "core_type": "aiv",
      "name": "add",
      "args": ["y", "b", "z"],
      "arg_directions": ["input", "input", "output"],
      "arg_storage_keys": ["alloc:y", "param:2:b", "param:3:z"]

注意 arg_storage_keys——task 0 的输出 y 和 task 1 的输入 y 都映射到 alloc:y， 这告诉依赖分析器它们访问同一块内存，因此存在 RAW 依赖。

提问：每个字段是什么意思？

Task — 原子执行单元

@dataclass(frozen=True)
class Task:
    task_id: int               # 全局唯一执行顺序编号（0, 1, 2, ...）
    func_id: int               # 函数类型编号（所有 matmul 调用共享同一个 func_id）
    core_type: str             # "aic"（矩阵核） | "aiv"（向量核） | "mixed"
    args: tuple[Any, ...]      # 参数列表，如 ("x", "w", "y")
    arg_directions: tuple[str, ...]      # 每个参数的读写方向
    arg_storage_keys: tuple[Any | None, ...]  # 每个参数的内存位置标识
    name: str | None = None    # 函数名，如 "matmul"
    outputs: tuple[str, ...] = ()  # v0.11: 显式输出 buffer（多输出场景）
字段含义类比
task_id执行顺序编号，唯一且非负执行步骤 1、2、3
func_id函数类型编号，多个 task 可共享"这是第几号菜谱"
core_typeAIC = 昇腾 NPU 矩阵计算单元；AIV = 向量计算单元这道菜用烤箱还是灶台
arg_directionsinput/output/inout/scalar/nodep哪些材料要加工、哪些是成品
arg_storage_keysparam:0:x = 入口参数 x；alloc:y = 分配的中间结果"面粉在 A 柜"——两个步骤都从 A 柜取面粉，就有依赖
outputs显式声明的输出 buffer storage key（如多输出 tuple）v0.11 新增：topk 返回 values + indices 两个输出

Dependency — DAG 的边

@dataclass(frozen=True)
class Dependency:
    producer: int   # 生产者 task_id
    consumer: int   # 消费者 task_id
    kind: str = "data"  # "data"(RAW) | "storage"(WAW) | "war"(WAR) | "ordering"

上面 matmul_bias 的例子：Dependency(producer=0, consumer=1, kind="data") — 必须先做完 matmul 才能做 add（RAW 数据依赖）。

Score.validate() 检查：producer/consumer 都指向已知 task、无自环、整个图是无环 DAG。

ShapeAssumption — 计划成立的前提条件

@dataclass(frozen=True)
class ShapeAssumption:
    symbol: str          # 参数名，如 "x"
    dims: tuple[int, ...]  # 形状维度，如 (32, 768)

ShapeAssumption 同时扮演两个角色：

  • 缓存条件：形状不同 → 不同的 fingerprint → 不同的缓存条目
  • 失效条件：运行时发现形状与假设不符 → 丢弃这个 Score，重新提取

例如：x 的形状从 [32, 768] 变成 [64, 768] → fingerprint 不同 → 缓存未命中 → 旧 Score 被跳过 → 新 Score 被提取。

动态维度如何处理？如果某个维度是 -1 或 0（PyPTO 用来表示"运行时才知道"）， Sonata 直接跳过这个参数的整个 shape assumption，而不是记录一个不完整的假设。 这保证了 Score 不会因为"假装知道"一个动态维度而失效。

RuntimeTarget — 怎么跑

@dataclass(frozen=True)
class RuntimeTarget:
    runtime: str = "tensormap_and_ringbuffer"
    function_name: str = "aicpu_orchestration_entry"
    aicpu_thread_num: int | None = 4

Sonata 支持两种目标：

  • host_build_graph：PyPTO 最简单的静态运行时，add_task() 加任务、add_successor() 加依赖边，与 Score 模型天然接近。eligibility 默认用这个
  • tensormap_and_ringbuffer：生产运行时，更复杂（动态 fanin、TensorMap 语义），留到 v0.3

提问：Score 的核心设计原则是什么？

计算 ≠ 执行。
Score 只描述"算什么"——任务、依赖、形状假设。
RuntimeTarget 描述"怎么跑"——目标运行时、入口函数、线程数。

这两层分离意味着：同一个计算计划可以适配不同的运行时配置，不需要重新提取 Score。 Inductor、XLA、TVM、CUDA Graphs 都采用了这个分离。

提问：怎么用代码构造和验证一个 Score？

from sonata import Score, Task, Dependency, ShapeAssumption, RuntimeTarget

score = Score(
    name="vector_add",
    runtime_target=RuntimeTarget(
        runtime="host_build_graph",
        function_name="build_vector_add_graph",
    ),
    tasks=(
        Task(task_id=0, func_id=0, core_type="aiv",
             args=("a", "b", "c"), name="add"),
        Task(task_id=1, func_id=1, core_type="aiv",
             args=("c", "out"), name="store"),
    ),
    dependencies=(Dependency(producer=0, consumer=1),),
    shape_assumptions=(ShapeAssumption(symbol="a", dims=(1024,)),),
)

result = score.validate()
if result.eligible:
    print("Score 是合法的")
else:
    print("拒绝原因:", result.reasons)

validate() 检查：name 非空、task_id 唯一且非负、func_id 非负、core_type 合法、 arg_directions/arg_storage_keys 与 args 长度匹配、dependency 指向已知 task、无自环、无环（DAG）、 shape symbol 唯一且维度为正整数。

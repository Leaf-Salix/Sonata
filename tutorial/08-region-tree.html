Tutorial 8 - Region Tree：层次化区域管理

提问：为什么需要 RegionTree？

考虑一个 PyPTO IR 函数，它的 body 有 5 条语句：

def my_graph(x, w, b):
    y = matmul(x, w)       # ← static
    z = add(y, b)          # ← static
    for i in range(10):    # ← dynamic (控制流)
        z = relu(z)
    o = softmax(z)         # ← static
    return o

v0.4 的 extract_regions() 会把它切成 3 个扁平区域：

RegionMap:
  Region 0: static   — [matmul, add]
  Region 1: dynamic  — [ForStmt]          ← fallback 到 AICPU
  Region 2: static   — [softmax]

问题来了：Region 0 和 Region 2 是独立的 static 区域，但它们之间有一个 dynamic 区域。 扁平结构看不出这种"static → dynamic → static"的交替关系。 如果 Region 0 的某个 guard 失效了，你只能全部重算——无法精确知道哪些区域受影响。

类比：RegionMap 像一张清单——列出所有区域，不分层次。 RegionTree 像一棵文件系统目录树——每个文件夹可以有子文件夹， 你可以单独删除某个子文件夹而不影响其他部分。

提问：RegionTree 从 RegionMap 构建时发生了什么？

用 build_region_tree() 把上面的 RegionMap 变成树：

from sonata.regions import build_region_tree

tree = build_region_tree(region_map)

构建算法的核心逻辑：

  1. 为每个 Region 创建一个叶子节点
  2. 找到连续的 dynamic 区域，归入其前面的 static 区域作为子节点
  3. 第一个 static 区域成为 root，后续节点成为 root 的子树

对上面的例子，结果是：

RegionTree: root = Region 0 (static: [matmul, add]) ├─ child[0] = Region 1 (dynamic: [ForStmt]) └─ child[1] = Region 2 (static: [softmax]) region_status: root → "mixed" （static 但有 dynamic 子节点） child[0] → "dynamic" child[1] → "static" （叶子节点，无子节点） static_subtrees(): root ← 最大静态子树的根（因为有 dynamic 子节点） child[1] ← 纯静态叶子

root 的 region_status 是 "mixed"——它是 static 节点， 但它的子树包含 dynamic 区域。这意味着 root 的 Score 不能直接使用， 需要和子节点的 fallback 策略配合。

提问：如果 IR 全是 static 会怎样？

def pure_static(x, w):
    y = matmul(x, w)
    z = relu(y)
    return z
extract_regions → RegionMap: Region 0: static — [matmul, relu] build_region_tree → RegionTree: root = Region 0 (static: [matmul, relu]) ← 单节点，无子节点 region_status: root → "static" static_subtrees(): [root] ← 整棵树就是一个静态子树

提问：如果 IR 全是 dynamic 会怎样？

def all_dynamic(x):
    for i in range(10):
        x = relu(x)
    while x.sum() > 0:
        x = x - 1
    return x
extract_regions → RegionMap: Region 0: dynamic — [ForStmt] Region 1: dynamic — [WhileStmt] build_region_tree → RegionTree: root = Region 0 (dynamic) ← 第一个区域就是 dynamic，standalone └─ child[0] = Region 1 (dynamic) check_region_eligibility → reject 原因: "all regions are dynamic, no static region available"

提问：RegionTreeNode 的数据结构是什么？

@dataclass(frozen=True)
class RegionTreeNode:
    region: Region                           # 区域类型（static/dynamic）
    children: tuple[RegionTreeNode, ...] = ()# 子节点
    score: Optional[Score] = None            # 该区域的 Score（静态区域才有）
    _fingerprint_cache: Optional[str] = None # 子树指纹缓存

每个节点是 frozen=True 的不可变数据类。"更新"就是创建新实例：

# 更新节点的 Score → 返回新节点，旧节点不变
new_node = node.update_score(new_score)

# 更新子节点 → 返回新节点，子树指纹重新计算
new_node = node.update_children((child1, child2))
不变性的好处：旧节点和新节点可以同时存在。 缓存系统用旧指纹找到旧条目，用新指纹存储新条目，不会互相干扰。

提问：子树指纹是怎么工作的？

每个节点的 fingerprint 是整个子树的 SHA-256 哈希值。计算时包含：

层级包含的字段
节点自身region_id, region_kind, node_count
Score（如有）score_name, task_count, dep_count, guard_count
子节点每个子节点的 fingerprint（递归）

关键特性：局部变化不影响全局。

假设 RegionTree: root (fp=abc123) ├─ child[0] (fp=def456) ← 如果这个节点的 Score 变了 └─ child[1] (fp=ghi789) 结果: root.fingerprint → 变了（因为 child[0] 的指纹变了） child[1].finger → 不变（兄弟子树不受影响） → 只需要重新缓存 root 和 child[0]，child[1] 的缓存仍然有效

提问：缓存怎么和 RegionTree 配合？

v0.11 添加了三个函数管理 RegionTree 的缓存。用一个完整例子演示：

from sonata.regions import (
    store_region_tree, lookup_region_tree, invalidate_region_tree,
)
from sonata import ScoreCache

cache = ScoreCache()

# 第一步：存储 —— 遍历树，为每个节点计算指纹并存入缓存
path_map = store_region_tree(tree, plan_handle_payload, cache)
# path_map 结果:
#   "root"         → "abc123..."
#   "root.child[0]" → "def456..."
#   "root.child[1]" → "ghi789..."

# 第二步：查询 —— 按路径查找某个区域的缓存
payload = lookup_region_tree("root.child[1]", cache, path_to_fingerprint=path_map)
if payload is not None:
    print("Region 2 命中缓存")  # ← 命中！

# 第三步：失效 —— 假设 ForStmt 的 guard 失效了
violated = tree.root.children[0]  # Region 1 (dynamic)
removed = invalidate_region_tree(tree, violated, cache, path_to_fingerprint=path_map)
# removed = 1（只清除了 child[0] 的缓存）
# root 和 child[1] 的缓存仍然有效
失效策略是保守的：只清除受影响节点及其子孙。祖先节点的缓存保留。 如果需要整棵树重算，调用 cache.invalidate_all()。

提问：RegionTree 有哪些查询方法？

tree = build_region_tree(region_map)

# 树级查询
tree.all_nodes         # BFS 遍历所有节点（返回 list）
tree.static_subtrees() # 所有"最大静态子树"的根节点
tree.dynamic_nodes()   # 所有 dynamic 节点
tree.static_ratio      # 静态节点占比（float）

# 节点级查询
node = tree.root
node.is_leaf           # True if 无子节点
node.region_status     # "static" / "dynamic" / "mixed"
node.is_static_subtree # True if 整个子树都是 static
node.fingerprint       # 子树的 SHA-256 指纹

region_status 三态

状态含义场景
"static"节点和所有子节点都是 static纯静态子树，可以完整规划
"dynamic"节点本身是 dynamic控制流节点，需要 fallback
"mixed"节点是 static，但有 dynamic 子节点部分可用，需要混合策略

提问：check_region_eligibility 返回什么？

result = check_region_eligibility(ir_node, entry_name="my_graph")

if result.eligible:
    meta = result.metadata
    print(f"Regions: {meta['region_count']}")        # 3
    print(f"Static: {meta['static_region_count']}")  # 2
    print(f"Dynamic: {meta['dynamic_region_count']}") # 1
    print(f"Static ratio: {meta['static_ratio']:.0%}") # 67%

    # 访问 RegionTree
    rt = meta['region_tree']
    for node in rt.static_subtrees():
        print(f"Static subtree root: region_{node.region.region_id} "
              f"({node.region_status})")

    # 访问每个区域的 Score（目前是 placeholder）
    for key, score in meta['per_region_scores'].items():
        print(f"{key}: {score.name}")
⚠️ 部分实现：per_region_scores 中的 Score 目前是 placeholder （空的 tasks/dependencies/shape_assumptions）。 真正的 per-region Score 提取（从 IR 子图独立提取）尚未实现， 属于 v0.13+ 规划。metadata 结构已就绪，等待后续填充。

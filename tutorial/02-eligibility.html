Tutorial 2 - Eligibility：谁有资格进入 Sonata？

提问：check_static_eligibility 做什么？

这是 Sonata 的入口函数。给它一个 IR 节点，它会判断：这个节点能不能被 Sonata 处理？ 如果能，返回一个 Score；如果不能，返回结构化的拒绝理由。

from sonata import check_static_eligibility, RuntimeTarget

result = check_static_eligibility(
    my_ir_node,
    runtime_target=RuntimeTarget(
        runtime="host_build_graph",
        function_name="build_my_graph",
    ),
    entry_name="my_function",
    dependency_policy="sequential_v0",
)

提问：什么样的节点会被拒绝？

Sonata v0.1 非常保守——整图 fallback。任何一个不支持的节点导致整个图被拒绝：

被拒内容FallbackCode说明
ForStmtcontrol_flow_not_supported循环语句（如 KV-cache 循环）
IfStmtcontrol_flow_not_supported条件分支
WhileStmtcontrol_flow_not_supported条件循环
RuntimeScopeStmtunsupported_runtime_scope运行时作用域
tensor.readtensor_read_not_supported数据读取操作
非 Orchestration 函数entry_function_not_orchestration只有编排函数可被提取
与 Inductor graph break 的区别：Inductor 遇到不支持的操作时，会保留支持的部分继续编译，不支持的 fallback 到 eager。 Sonata v0.1 是"整图 fallback"。v0.4 的 Regionized DAG 将把图切成多个区域，每个区域独立判断 eligibility—— 不支持的区域 fallback，支持的区域正常编译。

接受条件：根节点是 Function 或 Program，函数类型是 Orchestration，只包含普通 Call 语句。

提问：提取过程是怎么工作的？

1. 检查根节点类型  → 是否是 Function/Program？
2. 遍历所有子节点  → 有没有不支持的控制流或操作？
3. 找到提取根      → 确定从哪里开始（Orchestration 函数）
4. 构建 Score      → 提取 tasks、dependencies、shape_assumptions、metadata
5. 验证 Score      → 调用 score.validate() 做一致性检查
6. 检查存储覆盖率  → 如果内存参数的 storage key 覆盖率太低，发 warning

提问：_walk 是怎么遍历 IR 的？

_walk 是一个深度优先遍历器，使用结构化内省——不依赖具体的 IR 类，只看字段名：

child_fields = (
    "functions", "body", "then_body", "else_body",
    "branches", "stmts", "statements", "seq",
    "args", "value", "expr", "condition",
)

它用 hasattr 检查每个节点是否有这些字段，有的话就递归进去。 同时用 id(current) 做去重，避免循环引用。

这种设计的好处是：如果 PyPTO 改了 IR 的类名但保持字段名不变，Sonata 不需要修改。

提问：Task 是怎么从 IR 提取出来的？

_extract_tasks 的逻辑：

  1. 对每个提取根（Orchestration 函数），先用 collect_storage_keys 收集存储信息
  2. 遍历函数体里的所有 Call 节点
  3. 跳过内置操作（tile.、tensor.、system.、array. 开头的）
  4. 给每个 Call 分配 task_id 和 func_id
  5. 从 Call 的 args 和 arg_directions 构建 Task 对象
  6. 如果 Call 的输出被赋值给变量，传播 storage key 到输出变量

注意：PyPTO 的 Group/Spmd 函数会展开成多个 task（如 Group → AIC + AIV）， 但 Sonata 当前只按 Call 提取一个 task。v0.1 smoke 明确排除 Group/Spmd/Submit。

提问：ShapeAssumption 是怎么提取的？

_extract_shape_assumptions 从提取根的 params 提取：

  1. 取参数的 type / type_ / tensor_type
  2. 从类型里取 shape / shape_ / dims / dims_
  3. 每个维度必须是正整数（通过 is_static_shape_dim 检查）
  4. 遇到 -1 或 0 就跳过整个参数——不记录部分假设
  5. 如果有多个提取根，symbol 加函数名前缀（如 func_a.x）
def is_static_shape_dim(dim):
    """只有正整数才是静态形状维度。-1、0、bool 都不算。"""
    return isinstance(dim, int) and not isinstance(dim, bool) and dim > 0

提问：EligibilityResult 有几种状态？

result = check_static_eligibility(ir_node)

if result.eligible and not result.has_warnings():
    # 完全合格 — 使用 Score
    score = result.score

elif result.eligible and result.has_warnings():
    # 合格但有警告（如存储覆盖率低）
    # 仍然可用，但消费者应该知道置信度较低
    for w in result.reason_details:
        if w.severity == "warning":
            print(f"警告 [{w.code}]: {w.message}")

else:
    # 不合格 — 返回拒绝原因
    for r in result.reason_details:
        print(f"拒绝 [{r.code}]: {r.message}")

三种构造方式：

  • EligibilityResult.accept(score) — 完全合格
  • EligibilityResult.reject(*reasons) — 不合格，返回原因列表
  • EligibilityResult.accept_with_warnings(score, *warnings) — 合格但有警告

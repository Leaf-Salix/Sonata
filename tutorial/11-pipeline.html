Tutorial 11 - Pipeline：一站式分析入口

提问：为什么需要 pipeline？

前面的教程介绍了 Sonata 的各个子系统：eligibility、regions、guards、memory plan、 runtime adapter。在实际使用中，你需要依次调用这些模块，把它们的结果串联起来。

pipeline.py 把这些步骤封装成一个函数调用：

没有 pipeline 时（手动串联）： elig = check_static_eligibility(ir, entry_name="fwd") region_map = extract_regions(ir) region_tree = build_region_tree(region_map) region_elig = check_region_eligibility(ir) plan_handle = PlanHandle.from_score(elig.score) adapter = HostBuildGraphRuntimeAdapter() result = adapter.generate_region_aware(elig.score, plan_handle, region_statuses=...) # 6 步，需要了解每个模块的 API 有 pipeline 时（一步到位）： result = sonata_analyze(certified_ir, entry_name="fwd") # 1 步，返回包含所有结果的 SonataAnalysisResult

提问：sonata_analyze 怎么用？

from sonata.pipeline import sonata_analyze

# certified_ir 是 PyPTO pass pipeline 在 Simplify pass 之后的 IR dump
result = sonata_analyze(certified_ir, entry_name="forward")

if result.eligible:
    print(f"Tasks: {result.task_count}")
    print(f"Has plan: {result.has_plan}")

    # 访问 Score
    score = result.score
    print(f"Dependencies: {len(score.dependencies)}")

    # 访问 RegionTree
    rt = result.region_tree
    print(f"Static ratio: {rt.static_ratio:.0%}")

    # 访问 HostBuildGraphPlan
    plan = result.host_build_graph_plan
    for task in plan.tasks:
        print(f"  Task {task.task_id}: {task.name} ({task.core_type})")
else:
    for reason in result.fallback_reasons:
        print(f"[{reason.code}] {reason.message}")

提问：SonataAnalysisResult 包含什么？

@dataclass(frozen=True)
class SonataAnalysisResult:
    # Eligibility
    eligible: bool
    score: Score | None = None
    eligibility_result: EligibilityResult | None = None

    # Region analysis
    region_tree: RegionTree | None = None
    region_eligibility: EligibilityResult | None = None

    # Runtime plan
    plan_handle: PlanHandle | None = None
    host_build_graph_plan: HostBuildGraphPlan | None = None
    adapter_result: RuntimeAdapterResult | None = None

    # Metadata
    region_statuses: dict[str, str] = field(default_factory=dict)
    fallback_reasons: tuple[Any, ...] = ()
字段eligible=True 时eligible=False 时
score提取的 ScoreNone
region_treeRegionTree（层次化区域）None
plan_handlePlanHandle（运行时绑定）None
host_build_graph_planHostBuildGraphPlan（最终执行计划）None
fallback_reasons空拒绝原因列表

提问：sonata_analyze 内部做了什么？

sonata_analyze(certified_ir) 内部流程: Step 1: check_static_eligibility(ir) ├─ eligible → 继续 └─ not eligible → 返回 SonataAnalysisResult(eligible=False) Step 2: extract_regions(ir) → region_map build_region_tree(region_map) → region_tree check_region_eligibility(ir) → region_statuses Step 3: PlanHandle.from_score(score) Step 4: HostBuildGraphRuntimeAdapter().generate_region_aware( score, plan_handle, region_statuses=region_statuses) ├─ success → host_build_graph_plan └─ failure → host_build_graph_plan = None 返回 SonataAnalysisResult(eligible=True, ...)

提问：sonata_compile 是什么？

sonata_compile() 把 PyPTO 编译和 Sonata 分析合在一起：

from sonata.pipeline import sonata_compile

# program 是 @pl.program 装饰的类
compiled, result = sonata_compile(program, output_dir="./output", entry_name="forward")

if result.eligible:
    print(f"Plan: {result.task_count} tasks")
    # sonata_plan.json 已自动写入 output_dir

内部流程：

  1. 调用 pypto.ir.compile(program) 编译
  2. 运行 PyPTO pass pipeline，在 Simplify pass 之后提取 certified IR
  3. 调用 sonata_analyze(certified_ir)
  4. 如果 eligible，将 sonata_plan.json 写入编译产物目录
注意：sonata_compile 依赖 PyPTO 的 pypto.ir、 pypto.backend、pypto_core.passes 等模块。 在纯 Sonata 环境中（没有 PyPTO C++ bindings）无法使用。 纯测试用 sonata_analyze 即可。

提问：execute_with_sonata 是什么？

execute_with_sonata() 是运行时执行的包装器——在执行编译产物前， 先读取 sonata_plan.json：

from sonata.pipeline import execute_with_sonata

execute_result, sonata_plan = execute_with_sonata("./output", *inputs)

if sonata_plan is not None:
    print(f"Sonata plan: eligible={sonata_plan.eligible}, tasks={sonata_plan.task_count}")
else:
    print("No Sonata plan found, using default runtime")

向后兼容：如果 output_dir 里没有 sonata_plan.json， sonata_plan 返回 None，执行照常进行。

提问：sonata_plan.json 的格式是什么？

{
  "schema_version": 1,
  "eligible": true,
  "task_count": 5,
  "region_statuses": {
    "region_0": "static",
    "region_1": "dynamic",
    "region_2": "static"
  },
  "score": { ... },
  "plan_handle": { ... },
  "host_build_graph_plan": {
    "tasks": [
      {"task_id": 0, "func_id": 0, "core_type": "aic", "name": "matmul"},
      {"task_id": 1, "func_id": 1, "core_type": "aiv", "name": "add"}
    ],
    "edges": [
      {"producer": 0, "consumer": 1}
    ],
    "metadata": { ... }
  },
  "fallback_reasons": []
}

用 load_sonata_plan() 反序列化：

from sonata.pipeline import load_sonata_plan

plan = load_sonata_plan("./output")  # 自动找 sonata_plan.json
if plan is not None:
    print(plan.task_count)
⚠️ 部分实现：当前 load_sonata_plan 只恢复基本字段 （eligible 和 region_statuses），不恢复 score、plan_handle、host_build_graph_plan。 完整反序列化属于 v0.13+ 规划。

to_dict() / save() 已完整实现（✅）， 输出的 JSON 包含所有字段。但反向的 load 只读取部分字段。

提问：完整的端到端流程是什么？

PyPTO 编译 + Sonata 分析 + 运行时执行: ┌─────────────────────────────────────┐ │ @pl.program │ │ class MyModel: ... │ └──────────┬──────────────────────────┘ │ ▼ ┌─────────────────────────────────────┐ │ sonata_compile(program, output_dir)│ │ ├─ pypto.ir.compile() │ │ ├─ Pass pipeline → Simplify │ │ ├─ sonata_analyze(certified_ir) │ │ └─ write sonata_plan.json │ └──────────┬──────────────────────────┘ │ ▼ ┌─────────────────────────────────────┐ │ output_dir/ │ │ ├─ kernel_config.py │ │ ├─ sonata_plan.json ← Sonata │ │ └─ ... │ └──────────┬──────────────────────────┘ │ ▼ ┌─────────────────────────────────────┐ │ execute_with_sonata(output_dir) │ │ ├─ load sonata_plan.json │ │ └─ execute_compiled() │ └─────────────────────────────────────┘
总结：pipeline.py 是 Sonata 的顶层入口。 sonata_analyze 适合测试和验证； sonata_compile 适合 PyPTO 集成； execute_with_sonata 适合运行时执行。 三者配合 sonata_plan.json 形成完整的编译→执行链路。

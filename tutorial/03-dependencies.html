Tutorial 3 - 依赖策略：Sequential vs Dataflow

提问：Sonata 有两种依赖策略，有什么区别？

策略行为适用场景
sequential_v0 按提取顺序串行链接（task 0 → 1 → 2 → ...） task 的读写方向信息不完整时的保底策略
dataflow_v0 根据读写方向构建 RAW/WAW/WAR 依赖边，无依赖的 task 可并行 所有 task 都有完整的 arg_directions

提问：Sequential 是怎么工作的？

最简单——把所有 Task 按顺序串成一条链：

Task 0 → Task 1 → Task 2 → Task 3

Dependency(producer=0, consumer=1)
Dependency(producer=1, consumer=2)
Dependency(producer=2, consumer=3)

优点：永远正确，不需要任何额外信息。 缺点：可能过于保守——如果 Task 0 和 Task 2 没有数据依赖，串行执行浪费并行机会。

提问：Dataflow 是怎么工作的？

通过分析每个 Task 的参数读写方向来建立精确依赖：

读方向（input, inout）                  → 这个参数是"读"
写方向（output, outputexisting, inout） → 这个参数是"写"
忽略方向（scalar, nodep）               → 不参与依赖计算

三种依赖边：

  • RAW（Read After Write）：A 写了 x，B 读了 x → A 必须在 B 之前
  • WAW（Write After Write）：A 写了 x，B 也写了 x → A 必须在 B 之前
  • WAR（Write After Read）：A 读了 x，B 写了 x → A 必须在 B 之前

用一个具体例子说明：

# task 0: matmul(x, w, y)    — 读 x, w；写 y
# task 1: relu(y, y2)        — 读 y；写 y2
# task 2: add(a, b, c)       — 读 a, b；写 c
# task 3: mul(y2, c, out)    — 读 y2, c；写 out

# dataflow_v0 分析：
# - task 0 写 y → task 1 读 y  → 依赖边 (0→1) [RAW]
# - task 0, 1 与 task 2 无共享内存 → 无依赖 → 可并行！
# - task 1 写 y2 → task 3 读 y2 → 依赖边 (1→3) [RAW]
# - task 2 写 c  → task 3 读 c  → 依赖边 (2→3) [RAW]

# sequential_v0 则是简单的 (0→1→2→3)，不允许并行
# dataflow_v0 发现 task 0/1 和 task 2 可以并行执行，更高效

提问：Dataflow 需要什么前提条件？

每个 Task 必须有完整的 arg_directions，且长度与 args 一致。 如果某些 Task 缺少方向信息，Sonata 会自动降级到 Sequential：

# 在 eligibility.py 里
if requested_policy == DEPENDENCY_POLICY_DATAFLOW_V0:
    code = dataflow_dependency_fallback_code(tasks)
    if code is not None:
        return DEPENDENCY_POLICY_SEQUENTIAL_V0, code  # 降级

降级时记录的 fallback code：

  • DATAFLOW_DIRECTIONS_UNAVAILABLE — 所有 Task 都没有方向信息
  • DATAFLOW_DIRECTIONS_INCOMPLETE — 部分 Task 有方向信息但不完整

提问：storage key 在 Dataflow 里起什么作用？

当两个不同的参数名指向同一块内存时，只靠参数名会漏掉依赖：

Task 0: args=("buf",), arg_directions=("output",)   # 写入 buf
Task 1: args=("x",),   arg_directions=("input",)    # 读取 x

如果 buf 和 x 实际指向同一块内存，这里应该有 RAW 依赖。 arg_storage_keys 提供参数到真实内存的映射。在 dataflow 分析中：

access_key = storage_key if storage_key is not None else arg

有 storage key 用它做依赖判断，否则退回到参数名。没有 storage key 时，跨变量名的依赖会被漏掉。

提问：依赖类型有哪些？

Sonata 的 Dependency 有 kind 字段，区分四种依赖类型：

kind含义策略
"data"RAW（read-after-write）数据流sequential_v0 和 dataflow_v0 都产生
"storage"WAW（write-after-write）存储冲突dataflow_v0 分析
"war"WAR（write-after-read）反依赖dataflow_v0 分析
"ordering"纯顺序约束manual 或 fallback

sequential_v0 策略产生的所有边 kind 都是 "data"（保守并集）。 dataflow_v0 策略会根据 arg_directions 和 storage_keys 区分具体的 kind。

提问：怎么指定用哪种策略？

result = check_static_eligibility(
    node,
    dependency_policy="dataflow_v0",  # 或 "sequential_v0"（默认）
)

如果不指定，默认用 sequential_v0。

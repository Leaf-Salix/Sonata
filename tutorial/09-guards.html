Tutorial 9 - Guard 条件系统

提问：什么是 Guard？为什么需要它？

Sonata 的 Score 是在编译时生成的静态执行计划。 编译时做出的假设（比如 "batch_size = 32"）可能在运行时不再成立。 Guard 就是这些假设的运行时断言。

一个具体的场景：

# 编译时：输入形状 (32, 128)
score = check_static_eligibility(model, entry_name="forward").score
# score 包含: ShapeAssumption(symbol="batch_size", dims=(32,))
#             ShapeAssumption(symbol="seq_len", dims=(128,))

# 运行时：用户换了 batch_size
runtime_values = {"batch_size": 64, "seq_len": 128}
# batch_size 从 32 变成 64 → 假设失效 → 怎么办？
类比：你根据"今天 32°C"规划了户外烧烤。 Guard 就是"如果下雨就取消"。 你不需要重新规划所有细节——只需要检查一个条件，决定是继续还是切换。

提问：GuardCondition 的接口是什么？

v0.10 将 ShapeAssumption 抽象为 GuardCondition ABC。 任何 Guard 都必须实现 evaluate() 方法：

from abc import ABC, abstractmethod

class GuardCondition(ABC):
    symbol: str              # 可读标识符，如 "batch_size"
    severity: GuardSeverity  # "soft" 或 "hard"

    @abstractmethod
    def evaluate(self, runtime_values: dict[str, Any]) -> bool:
        """O(1) 运行时检查。True = 条件满足（guard 通过）。"""
        ...

O(1) 是硬性要求——每次 cache 查找都会执行所有 Guard 的 evaluate。

提问：soft 和 hard 有什么区别？

一个具体的例子说明区别：

Score 编译时假设: Guard A: batch_size == 32 (hard) ← 维度数不变，只是参数变了 Guard B: seq_len == 128 (soft) ← 序列长度可能变 场景 1: runtime_values = {"batch_size": 32, "seq_len": 256} Guard A: 32 == 32 → True (满足) Guard B: 256 == 128 → False (失效) 动作: INVALIDATE_HANDLE → 只需要重建 PlanHandle，Score 仍然有效（结构没变） 场景 2: runtime_values = {"batch_size": 64, "seq_len": 128} Guard A: 64 == 32 → False (失效) Guard B: 128 == 128 → True (满足) 动作: REPLAN → Score 和 PlanHandle 都失效，需要重新编译（形状假设变了） 场景 3: runtime_values = {"batch_size": 64, "seq_len": 256} Guard A: 64 == 32 → False (失效, hard) 动作: REPLAN ← 遇到 hard 失效立即短路，不再检查 Guard B
Severity含义失效动作典型场景
hard结构级变化REPLAN：Score + PlanHandle 都失效输入维度数变了、buffer 布局变了
soft参数级变化INVALIDATE_HANDLE：只失效 PlanHandlebatch_size 从 32 变成 64

提问：ShapeAssumption 现在怎么用？

ShapeAssumption 现在继承自 GuardCondition，向后兼容但已 deprecated：

# 旧写法（会触发 DeprecationWarning）
from sonata.score import ShapeAssumption
old = ShapeAssumption(symbol="N", dims=(128,))

# 新写法（推荐）— 显式指定 severity
from sonata.guard import ShapeAssumption, GUARD_SEVERITY_HARD
new = ShapeAssumption(symbol="N", dims=(128,), severity=GUARD_SEVERITY_HARD)

# evaluate 逻辑：runtime_values[symbol] == dims
new.evaluate({"N": (128,)})   # True
new.evaluate({"N": (64,)})    # False
new.evaluate({"N": None})     # False（缺少该符号）
迁移提示：ShapeAssumption 将在 v0.11 正式版移除。 请使用 GuardCondition 子类代替。 详见 docs/user-guide/guards-migration.md。

提问：GuardEvaluator 的完整工作流程是什么？

用一个端到端的例子展示从编译到运行时检查的完整流程：

from sonata.guard import GuardEvaluator, InvalidateAction
from sonata.plan_handle import GuardStatus

# 编译时：提取 Score 和 Guard
score = check_static_eligibility(model).score
guards = list(score.shape_assumptions)
# guards = [
#   ShapeAssumption(symbol="batch_size", dims=(32,), severity=HARD),
#   ShapeAssumption(symbol="seq_len", dims=(128,), severity=SOFT),
# ]

# 运行时：检查单个 Guard
evaluator = GuardEvaluator()
runtime = {"batch_size": 32, "seq_len": 128}

satisfied, action = evaluator.evaluate(guards[0], runtime)
# satisfied=True, action=REPLAN（hard guard，即使满足也预设最坏动作）

# 检查所有 Guard
all_ok, results = evaluator.evaluate_all(guards, runtime)
# all_ok=True
# results=[
#   (guard0, True, REPLAN),
#   (guard1, True, INVALIDATE_HANDLE),
# ]

# 如果 batch_size 变了
runtime_v2 = {"batch_size": 64, "seq_len": 128}
all_ok, results = evaluator.evaluate_all(guards, runtime_v2)
# all_ok=False
# results=[
#   (guard0, False, REPLAN),      ← hard 失效
#   (guard1, True, INVALIDATE_HANDLE),
# ]

提问：区域级 Guard 评估（evaluate_region）怎么工作？

v0.11 的关键新功能。用一个具体例子：

# RegionTree 结构:
#   root (Score: 2 tasks, 1 guard: batch_size==32)
#     ├─ child[0] (no Score, dynamic)
#     └─ child[1] (Score: 1 task, 1 guard: seq_len==128)

from sonata.guard import GuardEvaluator
from sonata.plan_handle import GuardStatus

evaluator = GuardEvaluator()

# evaluate_region 会递归收集 root + child[1] 的所有 guards
# 总共 2 个 guards: [batch_size==32, seq_len==128]

runtime = {"batch_size": 32, "seq_len": 128}
status = evaluator.evaluate_region(tree.root, runtime)
# → GuardStatus.ALL_SATISFIED

runtime_v2 = {"batch_size": 64, "seq_len": 128}
status = evaluator.evaluate_region(tree.root, runtime_v2)
# → GuardStatus.ALL_FAILED  (batch_size 是 hard guard，短路返回)

runtime_v3 = {"batch_size": 32, "seq_len": 256}
status = evaluator.evaluate_region(tree.root, runtime_v3)
# → GuardStatus.PARTIAL_FAILED  (seq_len 是 soft guard，不短路)
evaluate_region 递归过程: _collect(root): root.score.shape_assumptions → [batch_size guard] _collect(child[0]): no score → skip _collect(child[1]): child[1].score.shape_assumptions → [seq_len guard] guards = [batch_size==32 (hard), seq_len==128 (soft)] 逐个评估: batch_size==32, runtime=64 → False, action=REPLAN → return ALL_FAILED (短路!) seq_len==128 → 不再检查

提问：GuardSelector 怎么防止 over-guarding？

一个 100 个参数的 IR 会产生 100 个 Guard。 如果 fingerprint 包含所有 Guard 的哈希，任何一个参数变化都会使 fingerprint 失效—— 缓存命中率极低。这叫 over-guarding。

from sonata.guard import EntryParamGuardSelector, GuardEvaluator

# 假设一个大图有 100 个 ShapeAssumption
all_guards = score.shape_assumptions  # len = 100

# 用 GuardSelector 只选最重要的 10 个
selector = EntryParamGuardSelector(
    top_k=10,
    priority_symbols=("batch_size", "seq_len"),  # 这两个优先
)
selected = selector.select(all_guards)
# len(selected) = 10
# batch_size 和 seq_len 排在最前面

# 或者用 evaluate_region 的集成版本
evaluator = GuardEvaluator()
selected = evaluator.select_region_guards(
    region_node,
    selector=EntryParamGuardSelector(top_k=10),
    density_threshold=50,  # 超过 50 个 Guard 时发出 UserWarning
)

EntryParamGuardSelector 的策略：

  1. 先选 priority_symbols 中的 Guard
  2. 再按原始顺序添加剩余 Guard
  3. 最后按 top_k 截断

提问：InvalidateAction 和 GuardInvalidator 是什么？

from sonata.guard import GuardEvaluator, GuardInvalidator, InvalidateAction

evaluator = GuardEvaluator()
invalidator = GuardInvalidator()

# 端到端流程
runtime = {"batch_size": 64, "seq_len": 128}

# 第一步：评估
results = evaluator.evaluate_all(guards, runtime)
# results = [(guard0, False, REPLAN), (guard1, True, INVALIDATE_HANDLE)]

# 第二步：决策
action = invalidator.invalidate_all(results)
# → InvalidateAction.REPLAN（因为 guard0 是 hard 失效）

# 第三步：执行
if action == InvalidateAction.REPLAN:
    # 重新提取 Score
    new_score = check_static_eligibility(model).score
elif action == InvalidateAction.INVALIDATE_HANDLE:
    # 只重建 PlanHandle，复用 Score
    new_handle = PlanHandle.from_score(score)

提问：怎么自定义 Guard 类型？

from sonata.guard import GuardCondition, GuardSeverity

class MemoryBudgetGuard(GuardCondition):
    """检查运行时内存不超过预算。"""

    def __init__(self, budget_bytes: int):
        super().__init__(symbol="memory_budget", severity=GuardSeverity.HARD)
        self.budget_bytes = budget_bytes

    def evaluate(self, runtime_values: dict) -> bool:
        used = runtime_values.get("memory_used", 0)
        return used <= self.budget_bytes

    def to_dict(self) -> dict:
        base = super().to_dict()
        base["type"] = "MemoryBudgetGuard"
        base["budget_bytes"] = self.budget_bytes
        return base

    @classmethod
    def from_dict(cls, data: dict) -> "MemoryBudgetGuard":
        return cls(budget_bytes=data["budget_bytes"])

# 使用
guard = MemoryBudgetGuard(budget_bytes=512 * 1024 * 1024)  # 512 MB
ok = guard.evaluate({"memory_used": 100 * 1024 * 1024})     # True
ok = guard.evaluate({"memory_used": 600 * 1024 * 1024})     # False
设计原则：
  • Guard 必须是 frozen=True（不可变）
  • evaluate() 必须是 O(1)
  • 新增类型只需实现 evaluate()，可选覆盖 to_dict() / from_dict()

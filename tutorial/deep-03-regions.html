模块总览

extract_regions — 区域提取算法

def extract_regions(node: Any) -> RegionMap:

核心算法是一个单遍扫描，维护一个 static_buffer：

输入 IR body: [matmul, add, ForStmt, relu, IfStmt, softmax] 扫描过程: stmt=matmul → kind="Call" → 加入 static_buffer stmt=add → kind="Call" → 加入 static_buffer stmt=ForStmt → kind="ForStmt" → 切: 1. static_buffer 非空 → flush 为 Region 0 (static, [matmul, add]) 2. 创建 Region 1 (dynamic, [ForStmt]) 3. static_buffer 清空 stmt=relu → kind="Call" → 加入 static_buffer stmt=IfStmt → kind="IfStmt" → 切: 1. static_buffer 非空 → flush 为 Region 2 (static, [relu]) 2. 创建 Region 3 (dynamic, [IfStmt]) 3. static_buffer 清空 stmt=softmax → kind="Call" → 加入 static_buffer 扫描结束: static_buffer 非空 → flush 为 Region 4 (static, [softmax]) 结果: RegionMap([R0(static), R1(dynamic), R2(static), R3(dynamic), R4(static)])

RuntimeScopeStmt 特殊处理

RuntimeScopeStmt（PyPTO 的 MaterializeRuntimeScopes pass 插入的） 走单独的分支，使用 UNSUPPORTED_RUNTIME_SCOPE fallback code。

空 body 处理

如果 _get_body(node) 返回 None（节点没有 body/stmts/statements/seq 字段）， 调用 _classify_node() 对单个节点分类。

_get_body 的字段探测

def _get_body(node: Any) -> list | tuple | None:
    for field_name in ("body", "stmts", "statements", "seq"):
        body = getattr(node, field_name, None)
        if isinstance(body, (list, tuple)) and body:
            return body
    return None

按 body → stmts → statements → seq 顺序探测，返回第一个非空的。 这兼容了 PyPTO IR 的不同表示方式。

class RegionTreeNode:

region_status 三态逻辑

@property
def region_status(self) -> str:
    if self.region.is_dynamic:
        return "dynamic"
    if any(c.region.is_dynamic for c in self.children):
        return "mixed"
    return "static"

注意：只看直接子节点，不递归。如果孙节点是 dynamic 但子节点是 static， region_status 仍然是 "static"（子节点会是 "mixed"）。

is_static_subtree — 递归检查

@property
def is_static_subtree(self) -> bool:
    if self.region.is_dynamic:
        return False
    return all(child.is_static_subtree for child in self.children)

与 region_status 不同，这是递归检查整棵子树。

__post_init__ — 指纹缓存初始化

def __post_init__(self):
    if self._fingerprint_cache is None and self.score is not None:
        object.__setattr__(self, '_fingerprint_cache', self._compute_fingerprint())

因为是 frozen dataclass，必须用 object.__setattr__ 修改。 只有在 score 非 None 时才计算指纹——没有 Score 的节点不需要指纹。

_compute_fingerprint — 指纹计算算法

def _compute_fingerprint(self) -> str:
    base_identity = {
        "region_id": self.region.region_id,
        "region_kind": self.region.kind,
        "node_count": self.region.node_count,
    }
    if self.score is not None:
        base_identity.update({
            "score_name": self.score.name,
            "task_count": len(self.score.tasks),
            "dep_count": len(self.score.dependencies),
            "guard_count": len(self.score.shape_assumptions),
        })
    if self.children:
        base_identity["children"] = [child._compute_fingerprint() for child in self.children]

    payload = {
        "fingerprint_version": 1,
        "identity": {"type": "region_tree_node", **base_identity},
    }
    serialized = json.dumps(payload, sort_keys=True, default=str)
    return hashlib.sha256(serialized.encode()).hexdigest()

设计决策：为什么用独立的指纹函数而不是 score_fingerprint？

原因：score_fingerprint() 只计算 Score 的身份 （tasks、dependencies、shape_assumptions），不包含 region 元数据。 RegionTreeNode 的指纹需要包含 region_id、region_kind、node_count 以及子节点的递归指纹，所以必须用独立的计算逻辑。

注意：update_score 的指纹不一致

已知问题：update_score() 使用 score_fingerprint(new_score) 作为指纹，而 _compute_fingerprint() 计算的是包含 region 元数据的完整指纹。 两者不一致。目前 update_score 用于将节点绑定到特定 Score 的指纹， 但语义上应该用 _compute_fingerprint()。

update_score / update_children — 不可变更新

def update_score(self, new_score: Score) -> "RegionTreeNode":
    new_fp = score_fingerprint(new_score)
    return RegionTreeNode(
        region=self.region, children=self.children,
        score=new_score, _fingerprint_cache=new_fp,
    )

def update_children(self, new_children: tuple) -> "RegionTreeNode":
    return RegionTreeNode(
        region=self.region, children=new_children,
        score=self.score, _fingerprint_cache=self._compute_fingerprint(),
    )

返回新实例，旧实例不变。update_children 会重新计算整个子树指纹。

RegionTree — 树容器（v0.11）

@dataclass(frozen=True)
class RegionTree:
    root: RegionTreeNode

all_nodes — BFS 遍历

@property
def all_nodes(self) -> list[RegionTreeNode]:
    result, visited, queued = [], set(), set()
    queue = [self.root]
    queued.add(id(self.root))
    while queue:
        node = queue.pop(0)
        nid = id(node)
        if nid in visited: continue
        visited.add(nid)
        result.append(node)
        for child in node.children:
            cid = id(child)
            if cid not in visited and cid not in queued:
                queue.append(child)
                queued.add(cid)
    return result

使用 visited + queued 两个集合防止重复。 时间复杂度 O(n)（n = 节点总数）。

static_subtrees — 最大静态子树

def static_subtrees(self) -> list[RegionTreeNode]:
    return [
        node for node in self.all_nodes
        if node.region.is_static and (
            not node.children or any(c.region.is_dynamic for c in node.children)
        )
    ]

"最大静态子树"的定义：一个 static 节点，要么是叶子（无子节点）， 要么有至少一个 dynamic 子节点（static 血统在此中断）。

例子: root (static) ├─ child[0] (static) │ ├─ grandchild[0] (static) ← 最大静态子树的根 │ └─ grandchild[1] (dynamic) └─ child[1] (dynamic) static_subtrees() = [grandchild[0], root] grandchild[0]: static 叶子 root: static 但有 dynamic 子节点 child[1]

build_region_tree — 构建算法（v0.11）

def build_region_tree(region_map: RegionMap) -> RegionTree:

算法分三步：

Step 1：创建叶子节点

leaf_nodes = [RegionTreeNode(region=r) for r in region_map.regions]

Step 2：分组——动态归入静态

输入: [S0, D1, D2, S3, D4, S5] 扫描: i=0: S0 是 static → 找连续 dynamic: D1, D2 → grouped.append(S0.children=[D1,D2]) i=3: S3 是 static → 找连续 dynamic: D4 → grouped.append(S3.children=[D4]) i=5: S5 是 static → 无连续 dynamic → grouped.append(S5) grouped = [S0{D1,D2}, S3{D4}, S5]

Step 3：合并为树

grouped[0] = S0{D1,D2} 是 static 且 len(grouped) > 1 root = S0 existing_children = [D1, D2] subsequent = [S3{D4}, S5] all_children = [D1, D2, S3{D4}, S5] 最终 RegionTree: root = S0 ├─ D1 ├─ D2 ├─ S3 │ └─ D4 └─ S5
算法特点：所有非第一个区域都成为 root 的子孙。 这意味着树的深度最多为 2（root → grouped_node → children）。 如果需要更深的层次（比如嵌套控制流），当前算法不会产生更深的树。

check_region_eligibility — 区域级 eligibility（v0.4 + v0.11）

def check_region_eligibility(node, *, entry_name=None) -> EligibilityResult:

执行流程

1. extract_regions(node) → region_map

2. if all_dynamic → reject（收集所有 dynamic 区域的 FallbackReason）

3. build_region_tree(region_map) → region_tree

4. if 无 static 节点 → fallback 到 check_static_eligibility

5. 遍历 static_subtrees():
   - 为每个 static subtree 创建 placeholder Score
   - 存入 per_region_scores dict

6. 遍历 dynamic_nodes():
   - 收集 FallbackReason（补充 region_type 和 control_flow_node）

7. EligibilityResult.accept(score=None)
   - 通过 object.__setattr__ 注入 metadata:
     region_tree, per_region_scores, region_count,
     static_region_count, dynamic_region_count,
     static_ratio, static_subtrees, region_statuses

⚠️ per_region_scores 是 placeholder（未实现）

❌ 未实现：per_region_scores 中的 Score 是空的 （tasks=(), dependencies=(), shape_assumptions=()）。 真正的 per-region Score 提取需要从 IR 的子图中独立提取， 当前版本未实现。metadata 结构已就绪（✅），等待 v0.13+ 填充。

这意味着 check_region_eligibility 返回的 result.score 为 None， 应通过 result.metadata['region_tree'] 获取区域信息。

Per-Region Cache 函数（v0.11 Phase 1 C）

store_region_tree

def store_region_tree(
    region_tree, plan_handle_payload, cache, *,
    guard_status="all_satisfied", per_region_scores=None,
) -> dict[str, str]:

递归遍历树，为每个节点计算指纹并存入 cache。返回 {path: fingerprint} 映射。 路径格式："root"、"root.child[0]"、"root.child[0].child[1]"。

lookup_region_tree

def lookup_region_tree(
    region_path, cache, *, path_to_fingerprint=None,
) -> dict | None:

按路径查找缓存。如果 path_to_fingerprint 提供了，先映射路径到指纹， 再用指纹查 cache。返回 Score payload dict 或 None。

invalidate_region_tree

def invalidate_region_tree(
    region_tree, violated_node, cache, *, path_to_fingerprint=None,
) -> int:

找到 violated_node 在树中的位置，收集该节点及所有子孙的指纹， 调用 cache.invalidate(*fingerprints)。返回删除的条目数。

失效过程示意: RegionTree: root (fp=aaa) ← 保留（祖先不失效） ├─ child[0] (fp=bbb) ← violated！清除 │ └─ gc[0] (fp=ccc) ← 孙子，也清除 └─ child[1] (fp=ddd) ← 兄弟，保留 invalidate_region_tree(tree, child[0], cache, ...) → cache.invalidate("bbb", "ccc") → 返回 2
保守策略：只清除受影响的子树。祖先保留（它们可能包含其他有效子树的聚合信息）。 如果需要整棵树重算，直接调用 cache.invalidate_all()。

Sonata 术语表

本术语表解释了 Sonata 和 PyPTO 中常用的术语，帮助你更好地理解教程内容。

提示：你可以使用浏览器的搜索功能（Ctrl+F 或 Cmd+F）快速查找术语。

AICPU

AI CPU（AI Central Processing Unit）是昇腾 NPU 片上负责运行时图调度的 CPU 核心。 它在运行时负责分析依赖关系、决定执行顺序、分配和管理内存。

AIC/AIV 核心

AIC（AI Cube）和 AIV（AI Vector）是昇腾 NPU 上的计算核心， 分别负责矩阵运算和向量运算。Sonata 的任务可以指定在 AIC 或 AIV 核心上执行。

Block Dim

块维度，指 NPU 执行任务时的数据块大小。Sonata 可以建议最优的 block_dim 值。

conftest

pytest 的配置文件，用于定义测试 fixtures、hooks 和插件。 Sonata 使用 conftest.py 来注入 RUNTIME_CONFIG 和执行 compile hooks。

DAG

Directed Acyclic Graph（有向无环图），用于表示任务之间的依赖关系。 Sonata 的 Score 包含一个 DAG，描述任务的执行顺序。

Eligibility

资格检查，判断一个程序是否适合 Sonata 的静态调度。 如果程序包含动态形状或复杂的控制流，可能不符合条件。

Fallback

回退机制，当 Sonata 无法处理某个程序时，回退到 PyPTO 的默认动态调度。

Fingerprint

指纹，用于唯一标识一个 Score。基于 Score 的内容计算哈希值， 用于缓存和快速比较。如果两个 Score 的 fingerprint 相同，它们的内容也相同。

Guard

守卫条件，用于验证 Sonata 的假设是否仍然成立。 例如，如果 Sonata 假设输入张量的形状是固定的，guard 会在运行时检查这个假设。

HostBuildGraph

PyPTO 的运行时表示，描述了在主机端构建的任务图。 Sonata 生成的 Score 可以转换为 HostBuildGraph 格式。

importlib

Python 的模块导入系统，用于动态加载 Python 模块。 Sonata 使用 importlib 来加载 kernel_config.py 并读取 RUNTIME_CONFIG。

IR

Intermediate Representation（中间表示），编译器领域的术语， 指源代码和机器码之间的中间形式。在 PyPTO 中，IR 是模型的图形表示， 包含了所有的计算操作和依赖关系。

kernel_config.py

PyPTO 生成的配置文件，包含 RUNTIME_CONFIG 字典。 Sonata 可以将分析结果注入到这个文件的 RUNTIME_CONFIG["sonata"] 字段中。

Memory Plan

内存规划，Sonata 分析程序的内存使用模式，生成最优的内存分配方案。

NPU

Neural Processing Unit（神经网络处理器），专门用于加速深度学习计算的硬件。 PyPTO 和 Sonata 都是面向昇腾 NPU 的。

Pass Pipeline

编译器的优化通道，对 IR 进行一系列转换和优化。 PyPTO 的 pass pipeline 包含多个优化步骤，Sonata 在 Simplify pass 之后提取 IR。

Pipeline

Sonata 的顶层 API，提供一站式分析入口。 包括 sonata_analyze()、sonata_compile()、execute_with_sonata() 等函数。

PyPTO

面向昇腾 NPU 的深度学习编译框架。 Sonata 是 PyPTO 的可选增强，不修改 PyPTO 的核心代码。

Region

区域，Sonata 将程序划分为多个区域，每个区域可以独立分析和优化。 静态区域适合 Sonata 优化，动态区域保持 PyPTO 的默认行为。

RegionTree

区域树，Sonata 的层次化区域管理结构。 支持嵌套区域和 per-region 缓存。

RUNTIME_CONFIG

PyPTO 的运行时配置字典，定义在 kernel_config.py 中。 包含 runtime、block_dim、aicpu_thread_num 等字段。 Sonata 可以注入 sonata 字段来传递分析结果。

Schedule Contract

调度契约，Sonata 的目标产物。 描述了程序的静态执行计划，可以被运行时系统消费。

Score

Sonata 的核心产物——一个编译时提取的静态执行计划。 包含 tasks、dependencies、shape_assumptions 等字段。

ScoreCache

Score 缓存，基于 fingerprint 缓存 Score，避免重复分析。

simpler

PyPTO 的运行时包，包含平台后端（a2a3/a5）。 simpler 在执行编译产物时会读取 RUNTIME_CONFIG。

SonataAnalysisResult

Sonata 分析的结果，包含 eligibility、score、region_tree、plan_handle 等字段。

SonataRuntimeConfig

Sonata 运行时配置的数据类，用于嵌入到 RUNTIME_CONFIG["sonata"] 中。 包含 eligible、task_count、suggested_block_dim 等字段。

Storage

存储，Sonata 分析程序的内存存储模式，包括别名分析和生命周期分析。

ScheduleContract

调度契约，Sonata 的目标产物（v0.23+）。描述程序的静态执行计划，包括 static regions、 dynamic gaps、explicit deps、boundaries、guards、fingerprint、binding placeholders。 与 Score 不同，ScheduleContract 是 runtime-neutral 的，不绑定特定的运行时实现。

Backend Consumer

后端消费者，消费 ScheduleContract 的运行时实现。包括：

  • HBG backend：使用 HostBuildGraph 验证 schedule 拓扑正确性
  • Sonata TensorMap Hybrid backend：生产环境的混合执行实现
  • Future backend：未来可能的其他实现

Mixed Execution

混合执行，Sonata 的目标运行模式。静态区域（static region）使用 Sonata 的显式调度， 动态区域（dynamic region）保留 TensorMap 的自动依赖发现路径。 通过 sonata_tensormap_hybrid 实现。

TensorMap

PyPTO 的运行时依赖发现机制，自动管理张量之间的依赖关系。 Sonata 的静态调度可以替代 TensorMap 的动态发现。

TMARB

TensorMap and RingBuffer，PyPTO 的生产运行时系统。 包括 TensorMap（依赖发现）、RingBuffer（任务调度）、HeapRing（内存管理）等组件。 Sonata 的 ScheduleContract 必须能无损映射到 TMARB 的语义。

HBG

HostBuildGraph，PyPTO 的运行时表示，描述了在主机端构建的任务图。 Sonata 的 HBG backend 用于验证 schedule 的拓扑正确性。

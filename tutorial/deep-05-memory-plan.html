BufferAllocation — 单个 buffer 的分配

@dataclass(frozen=True)
class BufferAllocation:
    storage_key: str  # buffer 标识（如 "param:0:x"）
    offset: int       # 起始偏移（字节）
    size: int         # 字节大小

    @property
    def end(self) -> int:
        return self.offset + self.size

total_allocated

def total_allocated(self) -> int:
    return sum(a.size for a in self.allocations)

注意：这是所有 buffer 大小之和，不是峰值内存。 峰值内存 peak_memory 考虑了复用——两个不冲突的 buffer 共用同一块内存。

by_key

def by_key(self, storage_key: str) -> BufferAllocation | None:
    for alloc in self.allocations:
        if alloc.storage_key == storage_key:
            return alloc
    return None

线性查找。对于小规模 buffer 数量（通常 <100）足够快。

plan_memory — v0.3 贪心首次适配

def plan_memory(lifetimes, buffer_sizes) -> MemoryPlan:

算法详解

def plan_memory(lifetimes, buffer_sizes):
    if not lifetimes:
        return MemoryPlan()  # 空输入 → 空计划

    # 1. 构建冲突对集合
    conflicts = find_conflicts(lifetimes)
    conflict_pairs = set()
    for c in conflicts:
        conflict_pairs.add((c.key_a, c.key_b))
        conflict_pairs.add((c.key_b, c.key_a))  # 双向

    # 2. 按 size 降序排列
    sorted_lifetimes = sorted(lifetimes,
        key=lambda lt: buffer_sizes.get(lt.storage_key, 0), reverse=True)

    # 3. 逐个分配
    allocations = []
    for lt in sorted_lifetimes:
        size = buffer_sizes.get(lt.storage_key, 0)
        offset = _find_first_fit(size, lt, allocations, lifetimes, conflict_pairs)
        allocations.append(BufferAllocation(
            storage_key=lt.storage_key, offset=offset, size=size))

    # 4. 计算峰值
    peak = max((a.end for a in allocations), default=0)
    return MemoryPlan(
        allocations=tuple(sorted(allocations, key=lambda a: a.storage_key)),
        peak_memory=peak)

_find_first_fit — 首次适配算法

def _find_first_fit(size, lifetime, existing, all_lifetimes, conflict_pairs):
    if size == 0:
        return 0

    lifetime_map = {lt.storage_key: lt for lt in all_lifetimes}

    # 找出与当前 buffer 冲突的已分配 buffer
    conflicting = []
    for alloc in existing:
        other_lt = lifetime_map.get(alloc.storage_key)
        if other_lt is not None and lifetime.overlaps(other_lt):
            conflicting.append(alloc)

    if not conflicting:
        return 0  # 没有冲突 → offset=0

    # 按 offset 排序，找第一个能放下的位置
    conflicting.sort(key=lambda a: a.offset)
    candidate = 0
    for alloc in conflicting:
        if candidate + size <= alloc.offset:
            break  # 找到间隙！
        if candidate < alloc.end:
            candidate = alloc.end  # 跳过这个冲突 buffer

    return candidate
注意：_find_first_fit 同时使用 conflict_pairs 和 lifetime.overlaps()。实际上 conflict_pairs 在当前实现中没有被使用——冲突检测完全依赖 overlaps()。 conflict_pairs 是历史遗留参数。

compute_conflict_matrix — 冲突矩阵（v0.11）

def compute_conflict_matrix(
    lifetimes: list[BufferLifetime],
    *,
    stream_ids: dict[str, int] | None = None,
) -> list[list[bool]]:

算法

def compute_conflict_matrix(lifetimes, *, stream_ids=None):
    n = len(lifetimes)
    matrix = [[False] * n for _ in range(n)]

    for i in range(n):
        matrix[i][i] = False  # 自身不冲突
        for j in range(i + 1, n):
            # Stream 感知：不同 stream 不冲突
            if stream_ids is not None:
                si = stream_ids.get(lifetimes[i].storage_key, 0)
                sj = stream_ids.get(lifetimes[j].storage_key, 0)
                if si != sj:
                    continue

            if lifetimes[i].overlaps(lifetimes[j]):
                matrix[i][j] = True
                matrix[j][i] = True  # 对称

    return matrix

Stream 感知

昇腾 NPU 有多个计算 stream。不同 stream 上的 buffer 物理上并行执行， 内存独立。通过 stream_ids 参数标记每个 buffer 所属的 stream， 不同 stream 的 buffer 对永远不会冲突。

stream_ids = {"buf_a": 0, "buf_b": 1, "buf_c": 0} buf_a 和 buf_b 生命周期重叠，但 stream 不同 → 不冲突 buf_a 和 buf_c 生命周期重叠，stream 相同 → 冲突

时间复杂度

O(n²)——需要检查所有 buffer 对。对于 n < 1000 的典型场景足够快。

ConstraintSolver — 求解器 ABC（v0.11）

class ConstraintSolver(ABC):
    @abstractmethod
    def solve(
        self,
        conflict_matrix: list[list[bool]],
        sizes: list[int],
        device_memory_limit: int | None = None,
    ) -> MemoryPlan: ...

接口设计要点：

  • 输入是冲突矩阵（NxN 布尔），不是 BufferLifetime——解耦了 liveness 分析
  • device_memory_limit：可选的设备内存上限，求解器可以据此调整策略
  • 返回 MemoryPlan——包含 solver_type 标识

GreedySolver — 贪心首次适配递减（v0.11）

class GreedySolver(ConstraintSolver):
    def solve(self, conflict_matrix, sizes, device_memory_limit=None):
        n = len(sizes)
        if n == 0:
            return MemoryPlan(allocations=(), peak_memory=0, solver_type="greedy")

        # 1. 按 size 降序排列
        order = sorted(range(n), key=lambda i: sizes[i], reverse=True)
        offsets = {}

        # 2. 逐个分配
        for idx in order:
            size = sizes[idx]
            offset = 0
            placed = False
            while not placed:
                conflict = False
                for other_idx, other_offset in offsets.items():
                    if conflict_matrix[idx][other_idx]:  # 冲突检查
                        other_size = sizes[other_idx]
                        # 重叠检查：两个区间 [offset, offset+size) 和 [other_offset, other_offset+other_size)
                        if offset < other_offset + other_size and other_offset < offset + size:
                            offset = other_offset + other_size  # 跳到这个 buffer 之后
                            conflict = True
                            break
                if not conflict:
                    offsets[idx] = offset
                    placed = True

        # 3. 构建结果
        allocations = tuple(
            BufferAllocation(storage_key=f"buf_{i}", offset=offsets[i], size=sizes[i])
            for i in range(n)
        )
        peak = max((a.offset + a.size for a in allocations), default=0)
        return MemoryPlan(allocations=allocations, peak_memory=peak, solver_type="greedy")

与 plan_memory 的算法区别

plan_memoryGreedySolver
冲突检测BufferLifetime.overlaps()conflict_matrix[i][j]
首次适配扫描冲突 buffer 的 offset 间隙while 循环逐个跳过冲突 buffer
storage_key使用真实 key使用 f"buf_{i}"（丢失原始 key）
Stream 感知无通过冲突矩阵（上游处理）
已知限制：GreedySolver 使用 f"buf_{i}" 作为 storage_key， 丢失了原始 buffer 的标识。如果需要按 key 查找分配结果， 调用方需要自己维护 index → key 的映射。

GreedySolver 的时间复杂度

最坏情况 O(n² × m)，其中 n = buffer 数量，m = 冲突 buffer 数量。 实际中 m <<n（大部分 buffer 不冲突），所以接近 O(n²)。

solve_memory — 带超时的求解入口（v0.11）

def solve_memory(
    solver, conflict_matrix, sizes, device_memory_limit=None, *,
    timeout_seconds=1.0, fallback=None,

执行流程

def solve_memory(solver, conflict_matrix, sizes, device_memory_limit=None, *,
                 timeout_seconds=1.0, fallback=None):
    if fallback is None:
        fallback = GreedySolver()

    start = time.monotonic()
    try:
        result = solver.solve(conflict_matrix, sizes, device_memory_limit)
        elapsed = time.monotonic() - start
        if elapsed > timeout_seconds:
            warnings.warn(
                f"Primary solver took {elapsed:.2f}s (>{timeout_seconds}s). "
                "Consider using GreedySolver for large graphs.",
                UserWarning, stacklevel=2,
            )
        return result
    except Exception:
        warnings.warn(
            "Primary solver failed, falling back to GreedySolver.",
            UserWarning, stacklevel=2,
        )
        return fallback.solve(conflict_matrix, sizes, device_memory_limit)

超时是事后检查

关键限制：超时不会中断求解器。如果主求解器需要 10 秒， 它会完整执行 10 秒，然后发出警告。不会在 1 秒时中断。 这是因为 Python 的 time.monotonic() 只能测量时间，不能中断执行。 真正的超时需要求解器自身支持（例如传入 callback 或使用多进程）。

fallback 的触发条件

场景行为
主求解器成功，未超时返回主求解器结果
主求解器成功，超时返回主求解器结果 + UserWarning
主求解器抛异常返回 GreedySolver 结果 + UserWarning

注意：超时不触发 fallback——只发出警告。 只有异常才触发 fallback。这是因为超时的求解器可能已经给出了正确结果 （只是慢了点），而异常意味着求解器根本没完成。
